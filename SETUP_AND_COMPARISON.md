# Setup and comparison

## Minimal runtime

The controller uses Python 3.12, the standard library for runtime transport,
Git for patch/repository operations, and pytest only for repository test
commands and this project's development tests. No database, queue, browser,
GPU, or always-on service is required.

~~~bash
python -m pip install -e ".[dev]"
smartm2m smoke
~~~

## Model route

The lock file starts with DeepInfra openai/gpt-oss-120b because the assignment
allows any model and the route exposes an OpenAI-compatible endpoint. This is a
development choice, not evidence of quality or a recommendation. Both arms
must use the same resolved route, model identifier, service tier, decoding
parameters, local seed, retry policy, and budget.

The base URL, model name, credential environment variable, price snapshot, and
decoding settings are configuration fields. The key is never stored in the
repository. If the provider ignores seed or returns no usage, the run records
that limitation and does not silently treat unknown spend as zero.

## Reference command

The default reference command generated by the runner is equivalent to:

~~~bash
mini-extra swebench -c swebench.yaml -c configs/reference-overrides.yaml \
  --model openai/gpt-oss-120b --subset verified --split test \
  --workers 1 --filter '^(?:...)$' --output results/<run>/reference
~~~

The exact argv, package/version, stdout/stderr, and output files are captured.
Only configuration values are overridden; no reference source or prompt is
copied into the custom agent.

## Evaluator command

The default official command is:

~~~bash
python -m swebench.harness.run_evaluation \
  --dataset_name princeton-nlp/SWE-bench_Verified \
  --predictions_path results/<run>/<arm>/predictions.jsonl \
  --max_workers 1 --run_id <unique-run-id>
~~~

The evaluator runs after both sealed predictions exist. Its output is kept
under evaluation/reference and evaluation/custom and is the only source of
official resolution.

## Cost and scope choice

The starting budget is one attempt per task, 60 turns, 2,700 seconds wall time,
and a nominal 0.50 USD API threshold per episode. The limits are represented
in the lock and must be validated for the selected provider before freeze.
Unknown or retry-related spend remains visible. A larger model, multiple
providers, best-of-many attempts, and a web dashboard were deferred because
they weaken interpretability and deadline focus.
